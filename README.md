# My Recipe App README

Greetings,

Jason Griffin built this recipe app as his humble attempt to build something with the help of AI. He has an interest in cooking, so it seemed like a great place to start.

My goal was to create a very basic app with some useful features. The user can:

* Import recipes by copying a URL and entering them into the app.  
* Add recipes manually and add tags to them.  
* Search for recipes in a search field with optional filters.  
* Edit and/or create custom categories  
* Rate the recipes  
* Meal Plan  
* Create an inventory of their pantry and a shopping list  
* Export recipes in pdf format

## Look and device support

- System, Light or Dark theme, with 12 accent colors. Each accent uses one shade in both modes.  
- App icon picker (6 launcher icons).  
- Foldables and tablets: two panes side by side on wide screens, and a side navigation rail on expanded widths.  
- Backup & restore: everything goes into one `.zip` (recipes, photos, categories, plan, lists, pantry, settings). You can share it or save it anywhere with "Save as". Restoring lets you merge or replace. Older `.myrecipe` files still import.  
- Contact Us: sends email to Eve (Jason's assistant bot).

**Removed along the way** (the code is in git history): nutrition (Oct 3), receipt scanning (v1.0.1), sample recipes (v1.0.1), household sharing, cloud sync, sign-in, and the remote MCP server (all v1.0.6).

## CI workflows (`.github/workflows/`)

- **`android.yml` (Android APK).** Runs on pushes to `main`, PRs to `main`, `v*` tags and manual runs. Steps:
  1. Set up JDK 17 and Node 22, run `npm ci`, then typecheck, lint and tests.
  2. Run `expo prebuild --platform android --clean`.
  3. Run `./gradlew assembleRelease` for arm64-v8a and x86_64.
  4. Re-sign with apksigner so the APK has v1, v2 and v3 signatures. AGP leaves out v1 when minSdk is 24 or higher.
  5. Verify the signature, check 16 KB zipalign, fail if any blocked permission is present, and check the launcher icons and aliases.
  6. Upload the APK as the `my-recipe-app-apk` artifact (kept 14 days).


  A GitHub Release is published **only** for a pushed `v*` tag, or a manual run with `publish: true` and a tag. The tag must match `expo.version`, and an existing release is never overwritten.


- **`pages.yml`.** Publishes `site/` (a one-page placeholder) to GitHub Pages. The MCP OAuth consent page that used to live there was removed in v1.0.6.
- **`supabase-migrations.yml`.** Still applies `supabase/migrations/*.sql` to the old Supabase project when a migration lands on `main`. The app itself no longer talks to Supabase (see Architecture).

## Signing

- The release keystore lives only in GitHub Actions secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). CI decodes it into the runner temp folder and deletes it after the build.
- Without those secrets (local builds, fork PRs), the build falls back to the debug key with a warning, and a publish run fails.
- The same key has to sign every update. Never regenerate or rotate it without Jason's OK. A backup is kept outside the repo.

# Architecture in brief

```
src/app/            expo-router screens (tabs: Recipes, Meal plan, +, Shopping, More)
src/types/          Recipe and other record types, validation, schema migrations (single source of truth)
src/import/         THE import pipeline: importRecipe() — no React deps (docs/IMPORT_API.md)
src/cooking/        cook-with-me session state (docs/COOK_API.md)
src/storage/        repositories over a swappable KeyValueStore (AsyncStorage by default)
src/backup/         backup/restore format (docs/BACKUP.md)
src/entitlements/   feature gate (all features free; paywall-ready)
src/pantry/         barcode lookup (Open Food Facts + local cache)
src/lib/            pure helpers: recipe utils, ingredients/units, timers, shopping, theme
```

- **One way in.** Every recipe source (link, text, share intent, deep link, PDF) calls `importRecipe()`. The steps are: parse, validate, normalize, dedupe by source URL, save. Tests cover this for typed text, imports and PDFs.  
- **Screens stay thin.** Logic lives in UI-free modules (ESLint blocks React imports there), so a future server could reuse them.  
- **Recipes come first, and that's tested.** `__tests__/recipes-first.test.tsx` runs the whole recipe workflow with every optional feature hidden.  
- **Paywall-ready gating.** Each optional feature has a `FeatureId`, and every entry point checks it. Everything is free, with no billing code. Core recipe features are never gated.  
- **Design rules** are in `docs/DESIGN.md`: theme tokens only (a test fails on hard-coded colors), text never truncates, keyboard avoidance on every input, and 360dp checks.  
- **What's left of sync.** Stored records still carry sync-era metadata (UUIDs, timestamps, tombstones, and legacy `householdId` / `createdBy` fields that backups strip out). The Supabase project is still live and its old tables are still there. The last migration moved every household row back to its owner, so no data was lost. `@supabase/supabase-js` is still in package.json, and `.env.example` still lists Supabase variables. ## How a build ran (from `AGENTS.md`)

1. **Plan:** a short plan in the PR description with a yes/no done checklist.  
2. **Work:** small, focused PRs, one concern each. CI must be green before merging.  
3. **Self code review** of the whole diff (hard-coded colors, keyboard, truncation, tests). For bug fixes, a failing test comes first.  
4. **Compound:** record new lessons in `LESSONS.md` and list them under "Lessons learned" in the PR so Eve can copy the general ones to Jason's other repos.

Agents may not push `v*` tags or publish releases. `AGENTS.md` reserves that for Eve or Jason. Since Oct 4 the workflow follows the Compound Engineering plugin (plan → work → code review → compound). The Superpowers plugin was uninstalled that day, but two of its rules stayed: verify before saying something is done, and test-first bug fixes.

## Where the lessons live

- **`AGENTS.md`** holds the rules for any coding agent in this repo: stack, layout, commands, CI, signing, branch/PR rules, product rules, Cursor Cloud setup.  
- **`LESSONS.md`** is read before every build. It holds dated lessons from things that actually went wrong. A few examples:  
  - v1.0.8: tab labels looked fine by layout math but were cut off on Jason's phone. The rule now is to verify UI from real renders at 360dp.  
  - v1.0.8: a hard-coded orange leaked into five places.  
  - v1.0.9: a `flex: 0` shorthand collapsed the + tab slot on web.  
  - v1.0.9: screenshots attached as "evidence" turned out to be red error overlays. Open every screenshot before signing off.  
  - Process: batch changes into fewer versions, because every build plus review costs usage. Put reviewer checklists in the build prompt so one agent run is enough.
